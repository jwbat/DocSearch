# cdk/ — agent notes

Two stacks for DocSearch. See `README.md` for setup/deploy commands.

- `DocSearchStack` (`docsearch_cdk/docsearch_stack.py`): storage, i.e. the
  docs bucket and the manifest table.
- `DocSearchWebStack` (`docsearch_cdk/web_stack.py`): the read path, i.e.
  the Go API Lambda, the HTTP API, the site bucket, CloudFront (which also
  forwards `/manifest` and `/file-url` to the API), and the deployment of
  the built `../web` app. Depends on `DocSearchStack`.

## Guardrails

- `cdk deploy` and `cdk destroy` act on real AWS infrastructure. The user
  runs them. Prepare the change, run `cdk synth` / `cdk diff` (both
  read-only), and hand over the command, e.g.
  `AWS_PROFILE=personal cdk deploy --all`.
- The docs bucket and DynamoDB table in `DocSearchStack` use `RemovalPolicy.RETAIN`. This is
  deliberate (they hold the only copy of synced documents) — don't change it to
  `DESTROY`, even if it looks like a stray setting during cleanup.
- The site bucket in `DocSearchWebStack` is `RemovalPolicy.DESTROY` with
  auto-delete on purpose: it holds only build output, re-uploaded every
  deploy.
- `app.py` pins both stacks to the `personal` profile's account and
  `us-west-2` (`ENV`), so a deploy with other credentials fails instead of
  landing in the wrong account. Use `AWS_PROFILE=personal` for synth/diff
  that touches AWS.
- `FRONTEND_ORIGINS` in `app.py` holds the CloudFront domain as a literal.
  That is deliberate: passing it from `DocSearchWebStack` to the docs bucket
  in `DocSearchStack` would be a cross-stack cycle. Don't "fix" it into a
  reference. If the distribution is ever replaced, update the literal and
  deploy both stacks.
- Synth runs the builds: Go for the Lambda (`../go_files`) and
  `npm run build` for `../web` (needs `npm install` there). Each falls back
  to Docker if the tool is missing. The `cdk` CLI and npm need the newer nvm
  node; agent shells may need it put on `PATH`.

## Generated / not source

`cdk.out/`, `docsearch_cdk/__pycache__/`, and `venv/` are build artifacts —
don't read them for context and don't edit anything inside them.
`storage.yaml` and `web.yaml` are generated by `synth.sh`; they are committed
so template changes show up in git diffs. Regenerate rather than edit them.
